# CALDINA サイト

三重県志摩市のリラクゼーション／エステサロン **CALDINA**（有限会社エターナル）のサイト。
**2026年オープン予定の新店**です。

型として、和歌山県海南市のエステサロン Louise Rever のサイト
（`https://www.louiserever.com/` の静的コピー、取得日 2026-08-04）を使っています。
**別会社・別店舗です。**同系の店で作りが近いため、造りを借りているだけで、
中身は CALDINA のものに置き換えていきます。

`python3 _tools/check.py` が「他店を特定できる文字列 0件」を返す状態を維持してください。
**base64 と %XX の中まで復号して見ます。**どちらも実際にすり抜けたことがあります。

## ⚠️ 公開前に必ず読むこと

### 1. 予約フォームに受け口がありません

```html
<form action="javascript:TW_confirm('../cgiFolder/mail_send.php')">
```

`cgiFolder/mail_send.php` は**このリポジトリに存在せず、Vercel は PHP を動かせません**。
元サイトではサーバー側のPHPが受けていましたが、**新店なので引き継ぐサーバーがありません。**

一方で **全15ページのヘッダーと、携帯の下端の固定帯が「Web予約 24時間受付」と掲げています。**
このまま公開すると、**画面は正常に見えるのに予約が1件も届きません。**気づくまでに時間がかかります。

公開前にどちらかが必要です。

- **受け口を作る** ─ フォームサービス（Formspree / Basin 等）か Vercel の関数。
  現在の作りには CAPTCHA・CSRFトークン・ハニーポットが0件で、
  送信先アドレスが hidden で客側から送られている（base64）ので、作り直しになります
- **「Web予約」を下ろす** ─ 表示を電話・LINEに寄せる。オープンまでの暫定としては現実的です

### 2. `.vercelignore` で `cgiFolder/` を**まるごと**除外してはいけません

全15ページが、ここから8本を読んでいます。

```
corestyle.css / tieredworks_base|libs|ajax|modules|exts|spry.js / js/csLibrary.js
```

`tieredworks_spry.js` は**予約フォームの検証そのもの**です。
一度まるごと除外したまま公開しようとして、サイト全体が崩れる状態になっていました。
除外は「動かない・置く意味がないもの」だけに絞ってあります（理由は `.vercelignore` の中に書いてあります）。

### 3. Vercel の Root Directory は `site`

ここがずれると `vercel.json` が読まれず、`/sp/` の301もセキュリティヘッダも効きません。

## 起動方法

相対パス（`../assets/` など）で組まれているため、`file://` ではなく HTTP で開いてください。

```sh
cd site
python3 -m http.server 8899
```

トップ: http://127.0.0.1:8899/index.html

ウィンドウ幅を変えると追従します。`/sp/` は PC 版へ転送されます。

### Vercel に載せるときの設定

`vercel.json` は `site/` に置いてあります。**Vercel の Root Directory を `site` に設定してください**
（Framework Preset は Other、ビルドコマンドなし）。ここがずれると `vercel.json` が読まれません。

`/sp/` の301はこのファイルで完結するので、サーバー会社へ依頼する必要はありません。

**入れていないもの**：`index.html` → ディレクトリ形への301。
内部リンク399本が `index.html` を指しているため、入れると内部移動が毎回リダイレクトを挟みます。
重複は canonical（ディレクトリ形）で解消済みです。内部リンクを書き換えてから入れるのが順序です。

**まだ無いもの**：Content-Security-Policy。
Google Fonts / Font Awesome / Google Maps を読んでいるので、許可リストを作らずに入れると表示が壊れます。別作業として切り出しています。

全678ファイル / 4.5MB。

### sp/ の扱い

PC版が全幅対応したため、SP版15ページは役目を終えています。
中身は消さず、`<head>` 先頭に PC版への転送を入れ、`noindex` を付けてあります。

削除するときは **先にサーバー側で `/sp/(.*)` → `/$1` の301を張ってから**にしてください。
順序を逆にすると、既存の被リンクとブックマークが404になります。

## 編集の約束ごと

### 触らないもの

生成CSS（`css/site.css` / `css/G*/cssfiles/*` / `cgiFolder/corestyle.css`）の**構造は編集しません**。
ブロックID（`B000000xxx`）が HTML・CSSファイル名・JS初期化まで貫通しているため、
生成物の構造を直接触ると壊れやすくなります。

**例外：色の一括置換だけは生成CSSにも当てました（96箇所）。** 理由は3つ。
TieredWorks はもう再生成しないので上書きで失われる心配がない。
色の置換は構造を一切変えない。
そして生成CSS側に金が70箇所あるため、詳細度で上書きし続けるより安全です。
**構造については従来どおり `lr-common.css` から上書きしてください。**

上書きは `css/lr-common.css` に、**同じか一段上の詳細度で**書きます。
このファイルは `<head>` の最後に読み込まれるので、同詳細度なら後勝ちで効きます。

### 配色はロゴから採った

CALDINA のロゴの色を実測すると **色相31°・彩度22%**（温かみのある茶）で、
元の Louise Rever の金は **色相41°・彩度44%**（黄みの強い金）でした。別の金です。

ロゴがこの店の identity なので、**サイトをロゴに合わせました**。
やり方は「色相 −10°／彩度 ×0.55／**明度はそのまま**」の一括変換（457箇所）。
明度を動かさないので、検証済みのコントラスト比が崩れません。実際すべて改善しました。

| 組み合わせ | 旧 | 新 |
| --- | --- | --- |
| 本文と白地 | 6.66 | **7.89** |
| 補助文字と白地 | 5.35 | **6.39** |
| 本文とベージュ地 | 5.71 | **6.61** |
| **2px＝押せる線と白地** | **2.62（1.4.11 不適合）** | **3.30（適合）** |

差し色（トライアル価格）だけは比例変換だと 2.48→1.99 と悪化したので、
別に `#944A38`（白地 6.37:1）を起こしました。

**レイアウト目的の `!important` は使いません。** 現在 `lr-common.css` にある7件は
すべて `prefers-reduced-motion` の中（アクセシビリティ上の正しい用法）です。

### 予約フォームの「検証の印」

送信を押したとき、埋まっている欄には ✓ が付き、抜けている欄には理由が出ます。
**この表示は3回作り直しました。**残しておきたいのは、なぜその形なのかの部分です。

| 決めたこと | 理由 |
| --- | --- |
| **✓ は必須の記入欄だけに出す** | 任意の欄は空のままでも検証を通る（Spryはそう作られている）。一律に出すと、何も書いていない「予約希望日（第2希望）」や「メニュー」にまで ✓ が付く。**書いていないものに「できています」と出すのは嘘** |
| **選択肢の段には ✓ を出さない** | 予約種別・予約時間は必須だが、選んだ丸そのものが見えているので印は要らない。6列で折り返す段の末尾に付くと居場所がない。足りないときの「選択されていません」は従来どおり出る |
| **開いた時点では何も出さない** | `change` を1つでも発火させると、Spry が `validateOn:["change"]` でフォーム全体にぶら下がっているため全項目が検証され、**開いた瞬間に全部が「検証OK」になる**。印を入れるだけで送信内容は正しく入るので、通知は不要 |
| **日付欄に placeholder を置かない** | 欄の中の薄い字と、下の「例）」で同じ日付が2箇所に出て、入力済みに見える |
| 印の大きさは 16px 固定 | 以前 19×14 と 19×40 が混在していた。原因は予約時間の段を flex にしたことで、中の `<img>` が flex item として段の高さまで伸びていた |
| 印の絵は自作（`form-ok.png` / `form-ng.png`） | 元の Spry の絵は teal（青緑）でこの店の5色のどれでもなかった。2倍解像度で置いてある。白地に対して 金3.30:1・差し色6.37:1 ＝ 非文字の下限3:1を満たす |
| 地色は `#EFEAE6`（OK）と `#EADEDB`（漏れ） | 元は `#b8f5b1`（黄緑）と `#ff9f9f`。どちらもこの店の色ではない。`#EADEDB` は差し色から明度だけ上げて起こした |
| 文言は 12px / `#944A38` | 元は 10px の `#ff3333` で 3.64:1。**入力の可否を伝える文言なのに小さな文字の下限 4.5:1 に届いていなかった** |

**必須にした項目を2つ増やしました。**
`予約希望日（第1希望）` と `予約時間（第1希望）` は任意でした。
予約の申し込みなのに日時が空で届くと、サロンが電話で聞き直すことになります。
第2希望は任意のままです。

### ロゴは切り取らず全体を使う

いただいた紋章は **1000×935（縦横比 1.070）**。
一時期 `assets/logo.png` は**中央の帯だけを切り出したもの**（560×201／比2.79）で、
上の「C」の紋章と下の飾りが落ちていました。**クライアント様の意向で全体を使います。**

| | |
| --- | --- |
| 版 | **700×573 ／ 比 1.222 ／ 80KB**（切り抜き版の141KBより軽い） |
| 作り方 | 元データを128色に減色。280px幅と160px幅で原寸と見分けが付かないことを目で確かめて採用（そのままだと305KB、単色化＋アルファは文字が痩せる） |

#### 元データには「見えない余白」が26%あった

`getbbox()` は**完全な透明しか落としません**。この元データには絵から遠く離れたところに
**孤立したノイズ画素**（1画素・不透明度17〜19）が散っており、それが余白を押し広げていました。

```
絵の実際の範囲   (70,101)-(945,817)     ← 不透明度>8 が3画素以上ある行・列
落ちた余白       上101px  下145px       ← 962px のうち 26%
```

そのまま使うと、**画像の中の空白のぶんだけ「写真と文字の間が空いて見える」**ことになります。
実際そう指摘を受けました。切ったのは空白だけで、飾りは1pxも削っていません
（緩い切り／厳しい切りを300px幅で並べて目視確認済み）。

結果：ヘッダーの高さ 390pxで 367→**340px**、1440pxで 262→**248px**。
ロゴの上下の空きは CSS の 10px と 12px だけになりました。

**縦横比が 2.79 → 1.070 に変わるので、置いてある全ての場所で寸法が変わります。**
実測（変更前）：1440pxでロゴ280×262 に対しヘッダーの器が145pxしかなく、
ロゴが149pxはみ出してナビに重なっていました（絶対配置なので器が伸びない）。

そこで **ヘッダーをどの幅でも同じ組み（flex）に一本化**しました。
1040px以下では既に flex でしたが、1041px以上だけ絶対配置のまま残っていたのが原因です。
**幅で組みを分ける理由がありません。**

#### 頭の白い部分を主役にしない

紋章を大きく置くとヘッダーが伸び、**扉写真より頭の白い部分のほうが目立ちます。**
主役は写真から下なので、ロゴは小さく置きます。

| 幅 | ヘッダーの高さ | 扉写真の上端 |
| --- | --- | --- |
| 1440px | 248 → **182px** | 214px |
| 1040 / 780px | **164px** | 267px |
| 640 / 430px | **136px** | 136px |
| 390px | 340 → **152px** | 152px |

#### 並びは元の型のまま（2列）

```
タイトル（左上）
┌ ロゴ ┐            ┌ ご予約はこちら ┐   ← 右上
└      ┘            │ tel.…          │   ← その下
                    └ OPEN / Holiday ┘
```

ロゴを全体版にしたとき3つを1行に並べる flex に組み替えたので、
**予約ボタンが電話番号の「横」に来て別物になっていました。**
マークアップの順は `ロゴ → 予約ボタン → 電話` で元のままなので、
**格子で置き場所を指定するだけで元に戻ります**（HTMLは触っていません）。

- **641px以上** … 2列。ロゴは2段ぶちぬきで縦中央
- **640px以下** … 予約ボタンは下端の固定帯が受け持つので出さない。ロゴ左・電話右の1行

**携帯もPCと同じ「ロゴ左・電話など右」の横並び**に統一しました。
以前はロゴが1行を独占して中央に座り、それだけで画面の4割を使っていました。
320px幅だけは横に入らず `flex-wrap` で自然に縦積みへ落ちます（折り返す幅は増やしていません）。

| 場所 | 寸法 |
| --- | --- |
| ヘッダー ≥1041px | 150×123 |
| ヘッダー ≤1040px | 130×106 |
| ヘッダー ≤640px | 105×86（左） |
| フッターの連絡先 | 220×180（中央。`display:block` で `margin:0` だったので左に付いていた） |
| 携帯メニューの面 | 150×123（背の低い画面では110×90／出さない） |
| 404 | 230×188（縦積み中央なので大きいまま） |

#### 携帯メニューの面は「ロゴの高さ」で閾値が動く

面の中身は `padding-top ＋ ロゴ ＋ 余白 ＋ 8項目(407px) ＋ padding-bottom`。
**ロゴの比が変わると必要な高さが変わり、飾りを削る境目も動きます。**

| ロゴ | 必要な高さ | 収まらなくなる画面 |
| --- | --- | --- |
| 旧 200×72（比2.79） | 659px | 640px以下 |
| 全体版 150×140（比1.070） | **727px** | **727px以下** ― iPhone SE2/3・iPhone 8（667px）が入る |

比だけ変えて閾値を放っておくと、**その帯の端末で必ずスクロールが出ます**（実測 scrollHeight 728 > clientHeight 667）。
2段にしてあります ― **740px未満**でロゴを100×93に落として余白を詰め、**600px未満**で出さない。
320×568 / 375×667 / 390×667 / 390×700 / 414×736 / 390×844 / 430×932 の7つで
あふれ0・切れ0を実測しています。

なお `css/lr-common.css` に **`img[width][height] { height: auto }`** があり、
HTMLの `height` 属性は全ページで無効化されています。
属性は縦横比のヒントとしてだけ効くので、比が変わったら属性も直してください
（直さなくても表示は崩れませんが、読み込み中の場所取りがずれます）。

### 携帯は画面を使い切る

サンプル（退役させた `sp/`）と並べると、こちらのほうが余白が多く写真が小さいと指摘を受けました。
実測すると理由がはっきり出ました。

| | 直す前（画面390px） | 直した後 |
| --- | --- | --- |
| 本文の器 | 320px（**82%**） | **360px（92%）** |
| 写真（中央値） | 300px（**77%**） | **360px（92%）** |
| 4枚組の回遊札 | 2列で1枚175px（45%） | **1列** |
| LINEのQR | 90px（読み取りにくい） | **150px** |

余白の内訳は `#SF-outer-container` の20px ＋ **私が足した `.newslistdata` の15px**でした。
前者を15pxにし、後者を外しています。

#### `margin: auto` は格子の項目を縮める

札を中央に置くつもりで `margin-left/right: auto` を書いていました。
**格子（や flex）の項目に auto の余白を付けると「引き伸ばし」が無効になり、
項目は中身の幅まで縮みます。**
器が360pxあるのに札が写真の原寸300pxで止まっていたのはこれが原因でした。

```css
/* 誤 */ li { max-width: 420px; margin-left: auto; margin-right: auto; }
/* 正 */ li { width: 100%; max-width: 420px; justify-self: center; }
```

#### …と、広げすぎて戻した

次は「大きすぎます」と言われました。実測すると、行き過ぎていたのは**幅の数字だけではありません**でした。

| 画面390px | 広げた直後 |
| --- | --- |
| 写真 | 360px ＝ **版面の100%**（原寸300pxを1.20倍に引き伸ばし。大きいうえに眠い） |
| 画面640px | 写真は原寸の**1.40倍** |
| 札1枚の縦 | 443px。390pxの画面に**1.9枚**しか入らない |

#### ★ 直したのはコース札だけだった

同じ390pxの画面で、**4枚組の回遊札（`.lr-tiles`）は写真が360px＝画面の92%のまま**残っていました。

柄の切れ端が縦に並ぶだけなので、1列で積む幅では地紋を出しません。

札の上限は **380px ＝ 写真の上限340 ＋ 余白20×2**。340 は原寸300pxの1.13倍で、ここが拡大の上限になります。

### 作者が意図した改行を使う

元のHTMLには携帯用とPC用の改行が入っていました。


### 中途半端な改行を防ぐ

日本語は既定では **どの2文字の間でも折れます**。放っておくと
「こだわっ／て」「カウンセリ／ング」「部／分痩せ」のように語の途中で割れます。

```css
body { word-break: auto-phrase; }   /* 形態素解析で文節の切れ目を選んで折る */
/* 見出しには加えて */
line-break: strict;                 /* JISの禁則。開き括弧の直後・閉じ括弧の直前・長音や小書き仮名の前で割らない */
```

実測での違い（幅300px・20px）：

| | 結果 |
| --- | --- |
| なし | 「お客様が満足できる結果にこだわ」「って、施術・サポートしておりま」「す。」 |
| `auto-phrase` | 「お客様が満足できる結果に」「こだわって、施術・」「サポートしております。」 |

12ページ×8幅（96通り）で数えた語中の分断は **63件 → 0件**。
残る8件はどれも「トータルビューティー／サロン」のような複合語の継ぎ目で、語は割れていません。

#### ① `lang` が無いと、宣言しても何も起きません

全15ページは `xml:lang="ja"` しか持っておらず、HTMLでは**無視されます**。
`<html lang="ja">` を足して初めて効きました。
（合わせて読み上げ・字形の選択・検索にも効きます）

置換で直すときの罠：`\blang=` は `xml:lang=` にも当たります（`:` が語境界）。
`(?<![-:\w])lang\s*=` を使ってください。

#### ② `text-wrap: balance` とは併用できません

`balance` が勝って文節の判断が打ち消されます。
対応していないブラウザのために `@supports not (word-break: auto-phrase)` の中にだけ残してあります。

#### ③ 要素を数え上げてはいけません

`p, td, li, .gothic, .mincho` と並べていたら、how_to_choose の説明文がどれにも当たらず
768pxで「ニーズの高い“部／分痩せ”」と割れていました。
`word-break` は**継承する**ので `body` に一度書きます。
（`table.trial td.t_r` にうっかり `word-break: normal` と書いていて、そこだけ届いていなかったこともあります）

#### ④ 「これ以上縮められない幅」が変わります

`auto-phrase` にすると要素の min-content が **1文字ぶん → 一番長い文節ぶん** に増えます。
course_plan の料金表はこれで画面から21px出ました。手当てには3手かかっています。

| 試したこと | 結果 |
| --- | --- |
| `overflow-wrap: anywhere` を品名の列に | 表は収まったが、品名の列が「1文字でも成立する」ことになり **59px** まで潰れて「●ミ／ネラ」 |
| 品名の列に `width: 100%` | 自動割付では 100% が表そのものを器より広げ、430pxで表が1px出て字が2px重なった |
| **時間と価格の列に `width: 1%`** | 正解。自動割付の 1% は「中身に必要なだけ」の意味で、余りは指定の無い列へ回る |

#### ⑤ 文節の判定にも取りこぼしがあります

「お手伝／いいたします。」「お客様一人／ひとりに」「全身／脱毛」の3つは
どの幅でも割れました（`auto-phrase` 自身の判定です。切っても直りません）。
この3つだけ HTML 側に印を付けています。

```css
.lr-nb { white-space: nowrap; }
```

宣言ではなく語の側に印を付けるのは、これが**例外**だからです。増やさないでください。

#### ⑥ それでも入らないときは級を落とします

`auto-phrase` は文節で折るだけで、文節そのものは縮めません。
**文節が段より長ければ、結局どこかで割れます。**

| 幅 | 対処 |
| --- | --- |
| ≤359px | 見出し 24〜25px → 22px（320pxで文節が入り切らず「…いただく／ため」「施術・」が単独行になっていた） |

### 折り返す幅

新しい breakpoint を増やさず、次の3つだけを使います。どれもこのサイト自身が持っていた数です。

- **1040px** — 版面1000 + 左右の余白20×2。これ以下で版面が流動する
- **900 / 901px** — faq の分類ボタンを4列→2列に落とす点と、キャンペーン札を「写真＋本文＋申込」の格子に組む点。器861px以上で 写真400 ＋ 間30 ＋ 本文360 が必ず入る
- **640px** — サイトが `rel="alternate"` で宣言していた「ここからは携帯」の境目

高さの条件を1つだけ使っています ― **`max-height: 640px`**。
携帯のメニューの面で、8項目（51px×8＋罫＝407px）にロゴ（112px）を足すと519pxになり、
568pxの画面（iPhone SE）では入りません。飾りより一覧が一目で収まることを優先しています。

**それ以外は折り返す幅を使わずに組んでいます。** 主な手口は3つ。

| 手口 | 使いどころ |
| --- | --- |
| `max(0px, calc((100% - 700px) / 2))` | 読む段。**保つのは余白ではなく段の幅**。1000pxのとき余白150pxで元の設計と一致し、700pxを切ると余白0になって全幅で読める |
| `display: grid` ＋ 列数を固定 | 3枚組・6枚組の札。**枚数のまま幅だけ縮む**ので、何列に割っても最終行に空きが出ない |
| `flex-wrap: wrap` ＋ `flex: 1 1 <基準>` | 写真の横に表や本文を置く組み。**入らなくなった時点で自動で下へ回る**ので、幅を決め打ちしなくてよい |

### 段組みにするときの落とし穴

生成CSSは float を解除するために clearfix の擬似要素を持っています。

```css
#SF-contents .SF-module-container ul.thumbnailList:before { content:" "; display:table }
#SF-contents .SF-module-container ul.thumbnailList:after  { clear:both }
```

**これを消さずに `display:grid` にすると、擬似要素が段の枠を2つ占領します。**
3列の段組みに ::before ＋ li×3 ＋ ::after の5個が入るので、
1行目が「::before, li, li」、2行目が「li, ::after」になり、
3枚しかないのに2列＋1枚に見えます。実測で
`li が 313x260@y1622 / 313x260@y1622 / 313x260@y1932` と出て分かりました。

float をやめた器では不要なので `content: none; display: none` で外しています。
**flex にした器でも同じことが起きます。**

### 段は900pxで積む

`#SF-rowN` は flex、各段は生成CSSの px を基準値として持ったまま比率で縮みます。
**縮むだけでは足りませんでした。** 3段組の how_to_choose は画面768pxで段が **229px** まで潰れ、
写真100pxを引いた残り129pxに「おすすめメニュー▼」を流し込んでいました。

段の基準値は320px。3段なら `320×3＋余白40＝1000px` 要るので、
版面がそれを下回る画面では横に並べる意味がありません。積む閾値を **640px → 900px** にしています。

`flex-wrap: wrap` で「床を割ったら折り返す」も試しましたが、**駄目でした。**
折り返す器では段が基準値より縮まなくなり、700〜1024pxの全ページで
幅1000pxの段が器からはみ出しました（実測72組）。**縮むのは `nowrap` のままです。**

### ★ 縦並びの flex では `flex-basis` が「高さ」になる

**この1つで3回、大きな空白を作りました。** 症状はどれも
「中身より器のほうが背が高く、下にぽっかり空きが残る」です。

| 器 | 横並び用に持っていた宣言 | 縦並びで何が起きたか |
| --- | --- | --- |
| `.thumbnail`（写真） | `flex: 0 1 400px` | 中の写真223pxに対し器が **400px**。下に177pxの空白 |
| `.newslistdata`（本文） | `flex: 1 1 360px` | 中身283pxに対し器が **360px**。**申し込みボタンが77px下に離れた** |

`height: auto` を足しても直りません。**`flex-basis` の側を止める**必要があります。

```css
/* flex-direction: column の中では、この 400px / 360px は「高さ」 */
flex: 0 0 auto;
height: auto;
```

見分け方は「器の高さ ー 中身の下端」を測ること。
`getBoundingClientRect()` を親子で取って引き算すれば、余りが何pxか一発で出ます。
CSSを読んでも出てきません。`400px` は幅のつもりで書かれているからです。

### 申し込みボタンは「本文の列の下」に置く（格子で跨がせる）

campaign の札は 写真｜本文 の2列で、申し込みボタンはその下です。
flex では「2列目の2行目」を指定できないので、901px以上だけ格子にしています。

ここで**写真を2行に跨がせない**と、1行目の高さが背の高い方＝写真の250pxで決まり、
本文の短い札ではボタンが本文から **119px** 離れてぽつんと浮きます。

```css
#SF-contents #B000000163 ul.thumbnailList li .thumbnail { grid-row: 1 / span 2; }
```

2つ注意があります。

- 置き換えは `grid-column` だけで書くこと。`grid-area` の一括指定で左右を入れ替えると、
  行の終わりが `auto` に戻って**跨ぎが解けます**
- 跨がせるのは申し込みボタンを持つ札だけ。beginner の札に掛けると
  中身のない2行目ができ、札の下に `row-gap` の30pxだけが余ります

### ★ コメントの末尾に書き足すときは `*/` を消す

**同じ誤りを3回しました。** 既にあるコメントに一段落足すとき、元の `*/` を消し忘れる：

```css
   …従来の説明。 */
   ★ 追記した説明。 */
#SF-row1 { display: flex; }     /* ← これが丸ごと捨てられる */
```

CSS としては「余分な `*/`」で、そこから次の `}` までが**まるごと無視されます**。
捨てられるのは直後の規則なので、書いたはずの `display:flex` や `@media` が消えます。
**ファイルは何事もなく読め、波括弧の数も合います。**

3回とも、画面を測るまで気づけませんでした（`#SF-row1` の `display:flex` が消えて
700〜1024pxの全ページで段がはみ出す、`@media` が消えて料金表が3列のまま残る、など）。

`check.py` が `■ CSS の書き方` で見ます。

- コメントの入れ子・余分な `*/`・閉じ忘れ
- 波括弧の数
- **規則の外に日本語の文章が落ちていないか**（これが一番よく効きます）

### プライバシーポリシーは送信の前に置く

改修前、方針は **送信ボタンより下** にありました。

**止めるのは JS です。** このフォームの送信は `javascript:TW_confirm(...)` で横取りされていて、
HTML の `required` ではブラウザの検証が走りません（`js/lr-form.js` の `gate()`）。

JSが読まれなければボタンは押せるまま残します。**送れなくなる方が害が大きい**からです
（方針を先に見せるという目的は、並び替えだけで既に達しています）。

押せない間は枠を 2px の金から 1px の薄色へ落とします。
このサイトでは **2pxの金枠＝押せる**が11箇所すべてで成立しているので、
押せないものに同じ符号を与えません。

### 携帯のメニュー

**押しボタンは左下に固定。押すと項目だけの面が画面全体に出ます。**

最初は「50pxの帯を画面上端に貼り付けて、押すと項目が下に伸びる」形で作りましたが、
作り直しました。理由は3つ。

- 常に50pxの帯が居座り、扉写真の上によそ者が一段挟まる
- 押すと本文を押し下げるので、読んでいた場所が動く
- 「押したら、それだけの画面が一番上に出る」のが普通の作り

いまの配置は下の3つで対になっています。

| 場所 | もの |
| --- | --- |
| 画面の下端いっぱい | お電話 / LINE / Web予約（`.lr-cta-fixed`） |
| 左下（bottom 72px） | メニュー ― 押すと同じ場所で × に変わる |
| 右下（bottom 72px） | PAGE TOP ― 寸法と色をメニューと揃えてある |

#### 面が透けていた原因（重なりの文脈）

生成CSSがナビの器（`#B000000002` など15個）に

```css
position: relative;
z-index: 10;
```

を宣言していて、**そこが重なりの文脈になっています。**
その中で `z-index: 200` と書いても、外から見れば「10の塊」なので、
ヘッダー（`#Module-default-container` の z:100）と
下端の固定帯（`.lr-cta-fixed` の z:100）に負けて後ろに回ります。
実測で、白い面の上にロゴと電話番号が乗って見えていました。**器そのものを持ち上げないと直りません。**

#### 中央揃えは溢れると上が切れる

`justify-content: center` は、中身が器より高いと**上端がはみ出して手が届きません**
（320×568 でロゴが切れました）。
`flex-start` ＋ 先頭要素に `margin-top: auto` / 末尾要素に `margin-bottom: auto` にすると、
余っていれば中央、足りなければ上から素直に並んで全部たどれます。

#### 壊れない作り

畳むのは **`html[data-lr-nav="ready"]` が付いてから**です。
この印は `js/lr-nav.js` が「押す仕掛けを用意できた」時に自分で付けます。
JSが落ちれば印が付かず、従来の一覧表示のまま残ります ―
**押せないボタンだけが残る、という行き止まりを作らないため**です。

`<head>` の最後で付けている `html.lr-js` とは役割が違います。
そちらは「JSが生きている」という印で、いま見ているのは幕（プリローダー）だけです。

開閉の状態は **`aria-expanded` だけ**が持ちます。CSSはそれを見て描きます。
状態を2箇所に持たせると必ず食い違います。

面が出ている間は、後ろの位置を覚えて `overflow: hidden` にし、閉じたら戻します。
Esc と、面の中のリンクを押したときに閉じます。Tab は面の中で回します
（後ろの本文へ抜けると、見えていない要素に焦点が移って行方が分からなくなります）。

### ★ `<a>` はあるのに押せる面が無い ― 3回起きました

「押せないの？」と指摘されて気付いた不具合です。**リンクの数を数えても出てきません。**
`getBoundingClientRect()` で **`<a>` 自身の面積**を測ってください。

| 起きたこと | 実測 | 原因 |
| --- | --- | --- |
| コース札の矢印が押せない | `0 × 19px` | 唯一の子だった `arrow.png` を私が消していた。中身が無い `<a>` は面を持たない |
| おすすめ3枚が押せない | `313 × 80px`（札は313×420） | `<a>` を `inset: 0` で札いっぱいに広げたが、生成CSSの `.c_box2 { position: relative }` のほうが**近い先祖**で、そこが基準になっていた |
| 同上（携帯） | ― | `.c_box` にも同じ罠。`position: static` に戻して札を基準に戻す |

対処は共通です。**`<a>` を札全体に重ね、`aria-label` で行き先を言う。**

```css
#SF-contents .lr-card .c_box2 { position: static; }   /* 基準を札に戻す */
```

`position: relative` は「見た目が動かない宣言」なので安全に見えますが、
**中の絶対配置の基準を黙って奪います。** `inset: 0` が効かないときは、
まず先祖に `position` が付いていないかを疑ってください。

### 読み込み中の画面（プリローダー）

`js/lr-pre.js` ＋ `.lr-pre`。紋章が満ち、店の一句が一筆で書かれ、
続けて金の1px罫が句の左右から外へ引かれる。回るもの・点滅するものは無い。

> **輝きを研ぎ澄ます、志摩の隠れ家**

#### 出るのはセッションの最初の1ページだけ

`<head>` のインライン1行が `sessionStorage` を見て `html.lr-pre-on` を付ける／付けない
を決めます。2ページ目からは `.lr-pre` が `display: none` で、DOMには在るが出ません。

`localStorage` にはしていません。それだと**二度と出ない**ので、
翌週来た人は一度もこの一句を見ないことになります。
タブを閉じれば消える `sessionStorage` が「サイトに入るたび1回」の意味に合います。

**1回しか見ないので 3.1 秒かけています。**毎ページ出すなら絶対にこの長さにはしません。

#### ★ 動きの語彙を増やさない ― ここが設計の芯

このサイトの運動は**2つしかありません**。

| | |
| --- | --- |
| 線が引かれる | `transform: scaleX()` |
| 面が満ちる | `opacity` |

5,453行を数えると `transform` は `scaleX` と `rotate(45deg)` だけ、
**`translate` は0件、`filter` も0件**。例外ゼロで守られています。
`js/lr-reveal.js` の冒頭にも「translate も scale も rotate も、文字にも写真にも当てない」
「奥行きを主張しない宣言なので、出現が奥行きを匂わせた時点で語彙が壊れる」と書いてあります。

試して**却下した**ものを残します。どれも一見この店に合いそうに見えます。

| 却下したもの | 理由 |
| --- | --- |
| 紋章がぼける→澄む（`filter: blur`） | ぼけは被写界深度＝**奥行き**。影も角丸も持たない版面の宣言に正面から当たる |
| 文字がふわっと上がる（`translateY`） | `lr-reveal.js` が「現在のwebで最も配備された効果なので使わない」と名指ししている当のもの |
| 字間が締まる（`letter-spacing`） | 3つ目の運動になる |
| 幕が横へ滑って消える（`translateX`） | 同上。滑らせると輸入した動詞になる。左右の扉も同じ理由で `scaleX` で作った（そのうえで不採用） |

#### ★ ただし「満ちる」だけでは足りなかった

最初の版は 紋章が満ちる → 上句が満ちる → 下句が満ちる → 罫が引かれる で、
**引かれる動きが最後の1本しかありませんでした**（＝ほぼ全部フェード）。
「何か動きが欲しい」という指摘はここです。
語彙を増やさずに、**既にある「引かれる」を字にも当てました。**

一句が `clip-path: inset(0 100% 0 0)` → `inset(0 0 0 0)` で左から右へ開きます。
筆が走る向きと同じです。字を1つずつ出す仕掛け（SplitText 系）とは別物で、
滑らかに1本の動きとして通ります。
`clip-path` が効かない環境では `opacity` だけが残り、前の版と同じ絵になります。

#### ★ 「一回止まる」を2回直した

**1回目 ― 読点で止まっていた。**
最初は句ごとに2本の動きに分け、読点のところで 200ms 置いていました
（「読点を字ではなく時間で打つ」という設計）。
**画面では「一回止まる」と受け取られました。**
間を詰めるだけでは直りません ― 2本に分けると、
1本目の終わりで `--lr-e-draw` が減速し、2本目の始まりで加速するので、
繋ぎ目に必ず「溜め」ができます。**器ごと1本**にすれば曲線も1本になります。

**2回目 ― 書き終わりと罫のあいだで止まっていた。**
一筆にしたうえで長さを 1000ms にしたら、
**書き終わってから罫が出るまで 400ms 何も動きませんでした**（実測）。

| 時刻 | 進んだ距離 |
| --- | --- |
| 〜850ms | +149px |
| 〜1000ms | +93px |
| 〜1150ms | +45px |
| 〜1300ms | **+2px** |

`--lr-e-draw` は収筆の減速が長いので、1000ms だと末尾がほぼ止まります。
さらに器の右の余白30pxを開ける分も、そこに字が無いので止まって見えます。

直し方は2つ重ねました。**長さを 500ms（線を1本引く長さ）に戻す**、
そして**罫の開始を書き終わりに重ねる**（1200ms → 1000ms）。
結果、右端は 351→528→596→641→686→712→724→729px と一度も足踏みしません。

#### ★ 扉の演出は作ってからやめた

去り際に「左右2枚の面が外側を軸に `scaleX(1→0)` で引かれ、本文が中央から現れる」
形を作りました。クライアントの指示（「右と左に開かれる扉のような演出はいらない」）で
**やめました。** 幕はただ薄くなって消えます。

作ったときに踏んだ2つは、別の場所で再発するので残します。

**`animation` が持っている値は `transition` より強い。**
紋章と句には `lr-fill` が `animation-fill-mode: both` で載っています。
同じ要素に `html.lr-pre-done { opacity: 0 }` を足しても**効きません**。
実測では紋章と句が消えないまま残り、最後の `visibility` で**飛んで**いました。
動きを持たない包みを1枚かぶせて、そちらを消す必要があります。

**`visibility` を切る時刻は、最後の動きが終わってから。**
`0s 900ms` にしていたら、右の面が引き終わる前（1000ms）に消えて飛びました。

#### 時間は 200 と 500 の和だけでできている

| 時刻 | 起きること |
| --- | --- |
| 0ms | 紋章が満ちる（500） |
| **700ms** | 一句が左から右へ**一筆で**書かれる（500） |
| **1000ms** | 金の1px罫が句の左右から外へ引かれる（500）← 書き終わりに**重ねる**<br>（携帯は 500ms・紋章の下に1本） |
| 1500ms | 版面が完成 |
| | ── **1000ms 待つ**（500+500）。動かさないで見せる時間 ── |
| 2500ms | 幕が薄くなって消える（600） |
| 3100ms | 消え終わる |

★ **待つ 1000ms が一番の見どころです。** 動かさないことで読ませます。
クライアントの指示は「この形で少し待って／もう少し長くして」でした。

#### 罫は「余りを分け合う」flex ― ただし携帯では置き方を変える

`.kome_line` / `.lr-book-h` と同じ建具です。固定幅にすると器が狭いとき文字に乗ります。

**携帯では左右に置きません。** 320px では片側30pxしか残らず、
2行の文字塊の縦中央に短い毛が2本刺さって「点」に見えました（撮って確認）。

置き場所も2回変えています。最初は**句の下**にぶら下げましたが、
「スマホにしたら少しダサくなってる」と指摘を受けました。
線が何にも掛かっておらず、余って見えたからです。
4案（上へ／無し／器いっぱい／そのまま）を並べて撮り、**紋章と句のあいだ**に決めました。

| | |
| --- | --- |
| 役目 | 「1px＝仕切る」が戻る。仕切るものが上下に在る |
| 幅 | 150px ＝ 携帯の紋章の幅と同じ。偶然に見えない |
| 引く時刻 | 1000ms → **500ms**。紋章が満ちたらすぐ引き、その下に句が来る ― **上から下へ、置かれる順と同じ順で動く** |

句（700〜1200ms）と重なるので、ここでも一度も止まりません。

#### 閉じ込めない作り（3段）

| 段 | 何が消すか | いつ |
| --- | --- | --- |
| 1 | `js/lr-pre.js` | `window.load`（最短2500msは見せる） |
| 2 | `<head>` のインライン1行 | 4200ms後に無条件で `html.lr-pre-done`（幕の総尺3100msより後ろ） |
| 3 | CSS | `html.lr-pre-on` が付いていなければ `.lr-pre` は最初から `display: none` |

3段目が要点です。**JSが1行も動かない環境では、覆いがそもそも出ません。**
「JSが死ぬと真っ白なまま」が、この種の画面でいちばん多い事故です。

`lr-pre-done` が付いた瞬間から `pointer-events: none`。
消え切るまでの600msのあいだ、後ろの本文の操作を邪魔しません。

`prefers-reduced-motion: reduce` では最終状態を静止で見せ、
JS側も最短を **1100ms**（既存の数）に落とします。
動きを嫌う人に静止画を2.5秒見せるのは長いからです。

#### ★ 幕は「早送り」では撮れない

`--virtual-time-budget` はタイマーを早送りするので、**150ms を指定しても
幕が消えた後の本文しか撮れません**（実測）。検証用の道具は別に要ります。

  1. 枠の中の頁を読み込み、`html` から `lr-pre-done` を外し続ける
     （`MutationObserver`。head の保険と `lr-pre.js` の両方から後で付くため）
  2. `document.getAnimations()` を全部 `pause()` して `currentTime` を T にする
  3. 幕が消える `transition` だけは `cancel()`（T に送ると消えかけしか撮れない）

時間が止まっているので、そのうえで早送りしても絵は動きません。

#### 検査の側にも仕込みが要る

`verify.py` / `rules.py` は同じ窓に枠を並べて測ります。同じ origin なので
`sessionStorage` は親と枠で共有されます。**枠を作る前に「見た」印を置きます。**

```js
try{sessionStorage.setItem('lr-pre','1');}catch(e){}
```

置かないと、たまたま最初に読み込まれた1枚だけが幕に覆われたまま測られ、
`rules.py` に至っては撮った絵の全面が生成りの地になって罫も文字も1つも写りません。

**その代わり、幕の中の文字は自動検査の外に出ます。**別に測ってあります ―
15の幅（320 / 359 / 360 / 390 / 430 / 540 / 600 / 640 / 641 / 700 / 768 / 900 / 1040 / 1440 / 1600）で
上句・下句とも**常に1行**、器からのはみ出し0。
折れる場所は読点のうしろ1箇所しか構造的に存在しません（句ごとに別の器に入れてあるため）。

| | ≤640px | ≥641px |
| --- | --- | --- |
| 上句「輝きを研ぎ澄ます、」 | 161px | 178px |
| 下句「志摩の隠れ家」 | 108px | 120px |
| 器 | 262〜525px | 526〜560px |

**一句を書き換えたときは、この表を測り直してください。**

## スクロールに合わせた出現

画面に入ってから出す。**役割ごとに動きが違う。**
実装は `js/lr-reveal.js` ＋ `css/lr-common.css` の「役割ごとの出現」節。

### 役割 → 動き

このサイトの運動は3つしかありません。それを役割に割り当てます。

| 役割 | 動き | 対象と数 | なぜその動きか |
| --- | --- | --- | --- |
| 罫 | **引かれる**（`scaleX`・外へ） | `.kome_line` 25 ／ `.lr-book-h` 15 | 線が外へ伸びて「ここが節だ」と場を開く（既存・スクロール位置で進む） |
| 節の見出し | **満ちる**（`opacity`） | `h2.headlineStyle` 27（開閉4個を除く） | 場が開いたことを受けて題が在る |
| 札の名前 | **書かれる**（`clip-path`・左→右） | `.newslistHeadlineStyle` 105 | 左寄せで器の幅が札の幅。字が読む向きに現れ、下罫も「題の始まりから外へ」引かれる |
| 札 | **満ちる**（`opacity`） | `.thumbnailList > li` 105 ほか | **1枚の紙**として。写真と本文をばらばらに出さない |
| 装飾 | **満ちる**（`opacity`・いちばん遅い） | 9ブロックの `::before` | 飾りは最後に置かれる。`::before` だけなので本文に触らない |

順番は**幾何が決めます。** 節の見出しは札より上に在るので先に画面へ入ります。
遅れの数字（`--lr-d`）を持つのは札だけで、同じ親の中での順番×100ms（6枚で頭打ち）。
ページ通しの番号だと下のほうの札が全部 500ms になって間が意味を失います。

読めない濃さになります。

### ★ 「字が書かれる」を当てられなかった場所

節の見出しに `clip-path` の掃き出しを当てようとして、2通り試して2通り駄目でした。

| 向き | 何が起きたか |
| --- | --- |
| 左→右 | `clip-path` の基準は border-box なので、**見出しが持つ金の罫まで字と同じ速さで左から拭われた**。実測98個（`inset(0 50% 0 0)` で上下の罫の金の画素がちょうど500個・x=140..639 で切れた）。このサイトの掟「罫は見出しから外へ向かって引かれる」に逆らう |
| 中央→外 | 器は版面幅1000pxなのに字は中央の約200pxだけ。**30%開いた時点で字が全部読めてしまう**（撮って確認）。動いているのは罫だけ |

**掃き出しは、器が字に沿っている場所でしか意味を持ちません。**
札の名前（左寄せ・器の幅＝札の幅）はそうなので、そちらに当てています。

### ★ 走り終えたら animation を外す（1pxの罫が薄くなる）

`opacity` のアニメーションが載っている間、その要素は自分の層に描かれます。
終わった後も載せたままにすると **1pxの罫が薄くなります**。

| 札の題の下罫 | |
| --- | --- |
| 出現あり（animation を載せたまま） | `(192, 173, 149)` |
| 出現を打ち消したとき | `(174, 150, 122)` |

このサイトの罫は署名なので、薄くなるのは許容できません。
`animationend` で `data-lr-done` を付け、CSS で `animation: none / opacity: 1` に戻します
（`opacity: 1` を明示しても層は作られません。1未満のときだけ作られます）。
直した後、**外部iframe（Google Maps）以外の差は0行**になりました。

### 閉じ込めない作り（5段）

| 段 | 何が守るか |
| --- | --- |
| 1 | `prefers-reduced-motion` なら何もしない |
| 2 | `IntersectionObserver` が無ければ何もしない（印が付かない＝伏せない） |
| 3 | 印を付ける・observe する・`html.lr-io` を付ける を**同じ同期処理**で行い、例外なら `lr-io` を外して帰る |
| 4 | **幾何で見る掃き取りを併走**。スクロールと寸法変更のたびに矩形を測り、画面に入っていれば出す。IO に依存しない |
| 5 | 3秒たって1つも出ていなければ全部出す |

加えて `@media print` では伏せません。紙にはスクロールが無いので、
観測の通知が来ないまま白紙で刷られます。

#### なぜ4段目が要るのか

**IO の通知は「描画の機会」に紐づいて配られます。**
headless で測ると、観測を張り直しても callback が**0回**でした。
`scrollTo` で `scrollY` は動くのに `scroll` イベントも発火せず、
始まった animation も `playState=running` のまま `currentTime=0` で止まりました
（`document.timeline` は 4788ms 進んでいるのに）。

実機では届きます。が、届かない条件が在ることが分かった以上、
中身が消えたままになる経路を1本残すことになります。
**矩形は読めばいつでも正しい。** 掃き取りが最後の担保です。
副産物として、スクロールで進むので `_tools/reveal.py` で実測できます。

### CLS を出さない

使うのは `opacity` と `clip-path` と `scaleX` だけ。3つとも版面を動かしません。
`_tools/reveal.py` が送りながら、版面の高さと各要素の文書内 y 座標が
1pxも変わらないことを確認します。

### 携帯ではさらに控えめに

**動くのは札だけ**にします。字の掃き出しは掛けません
（小さい画面では画面幅いっぱいの動きになり「静か」ではなくなる）。
間（`--lr-d`）も作りません ― 画面に1〜2枚しか入らないので、
順番は「律動」ではなく「待たされ」になります。

### 「重なり」は行box単位で測る

要素の矩形で測ると、float の隣にある段落が必ず誤検出になります。
そのため文字の**行box**（`Range.getClientRects()`）同士で測っています。

見えていないものを外すのに、**3つとも必要**でした。どれか1つでも欠けると誤報が出ます。

| 外すもの | なぜ必要か |
| --- | --- |
| 切り抜かれている矩形 | 判定は**その要素自身から**遡る。祖先だけ見ると足りない ─ 予約フォームの個人情報の箱 `#B000000313` は `height:200px / overflow:auto` に対し中身が1167pxあり、溢れた927px分の行boxが箱の下にそのまま並んで、予約の帯や著作権表示と重なって見える |
| 1×1 に潰した要素 | 読み上げ専用の隠し文字（`.lr-sr`）は `clip: rect(0 0 0 0)` で隠しているが、**clip は行boxの座標を変えない**ので必ず引っかかる |
| `.flexslider` `.slides` の中 | 扉写真は複数枚が同じ位置に重ねてある（これは重なって正しい） |

### 固定の高さ＋`overflow:hidden` は中身を黙って捨てる

生成CSSは器に `height:410px` のような固定値を持たせたうえで `overflow:hidden` を掛けています。
**原稿や画像が伸びると、はみ出した分が何も言わずに消えます。**
表示が壊れるわけではないので、見ていても気づけません。実際に3回起きました。

| 器 | 消えたもの | 量 |
| --- | --- | --- |
| `#B000000031` | 「Contact」ボタンの下半分 | 26〜38px |
| `#B000000030` | 営業日カレンダーの下（元はブログのiframe用の箱） | 235px |
| `.wrap`（index の `<style>`） | **トップだけ「© CALDINA」のフッターが丸ごと** | 100px |

3つとも**高さで持つのをやめました**。`.wrap` は 100vw の帯が横にはみ出すのを抑えるための
指定なので、`overflow-x: clip; overflow-y: visible` にして横だけ切ります
（`clip` は視覚だけを切りスクロール容器を作らないので `visible` と組み合わせられます）。

`_tools/verify.py` が常に見ます。判定は「中身が器より高い」ではなく
**「器の下端より下に、実際に矩形を持つ子孫がいるか」**です ―
扉写真は内部構造の都合で9pxの差が出ますが、器の外に出ている子孫は無いので誤検出になりません。
検査そのものを両方向で確かめてあります（`.wrap` の上書きを外すと320pxで検出、戻すと0）。

### 罫の貫通は「描画された画素」でしか捕まらない

`_tools/rules.py` は Chrome を1回起動して `--screenshot` と `--dump-dom` を
同時に取り、**画素で見つけた罫**と **DOMの行box**を突き合わせます。

判定には3つとも必要でした。どれか1つでも欠けると使い物になりません。

| 条件 | これが無いと |
| --- | --- |
| 罫が文字の幅の中を実際に通っている（その区間で85%以上が非地色） | `.kome_line` は罫が文字の左右にあって高さが同じなので、必ず誤検出になる |
| 罫が「字面」の上下端の内側にある | beginner の「4.」は61pxの数字で行boxが88pxあり、見出しの下罫がその中に入る |
| 重なりの「量」では判定しない | 1pxの罫と行boxの重なりは1pxしかない。閾値を2pxにして**既知の不具合を見落とした** |

検査そのものを両方向で確かめてあります ―
`body` の上書きを一時的に外して bg.png を復活させると6件を正確に指し、
戻すと 11ページ × 6幅すべてで0件になります。
